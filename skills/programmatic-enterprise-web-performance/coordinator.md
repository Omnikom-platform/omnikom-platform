# Programmatic Enterprise Web Performance — coordinator brief

You are the coordinator of a codebase check. You don't read the codebase yourself; workers do. Your inputs (from the prompt): repo root, focus, max parallel workers. Skill dir: `C:\Users\DELL\.claude\skills\programmatic-enterprise-web-performance` (`$SKILL` below).

Write scripts to files and run them; never inline `node -e` or heredocs. Run long commands in the background and wait on them; don't sleep-poll.

## Steps
0. **A live site (the input is a URL, not a folder).** Get its snapshot, then treat the snapshot folder as the repo root for every step below: `node "$SKILL/scripts/live-target.mjs" <url> [-- <snapshot options from the prompt>]` prints `REUSE <dir>` (a complete snapshot younger than 7 days: use it, do not re-crawl) or takes a new one (run it in the background; about 1 minute per page because it is deliberately slow and polite) and prints `NEW <dir>`. Exit 3 from the snapshot means the site rate-limited it twice and it stopped; exit 4 means the run time cap: check what was saved and report the stop; never re-run it in a loop. Pass `--ignore-robots` only when the prompt says the site belongs to the owner. If the prompt says the site is a preview (noindex by design), put that in the focus so workers do not report it as a defect.
1. **Plan.** `node "$SKILL/scripts/plan.mjs" "<repo>"` writes `<repo>/.checks/plan.json` (slices of ≤ 200 KB of source each, files of one directory kept together; binaries, lockfiles, vendored and generated files left out and listed; pages built from one template are grouped into families and only 2 representatives per family are sent, the workers are told which family each stands for). Read the summary it prints, including the families line: a family that lumps clearly different page types together is a planner error, so report it. If there are more than 12 slices, stop and return the slice count and the top-level folders, so the main session can confirm the cost or narrow the focus.
2. **Launch workers.** `node "$SKILL/scripts/launch-workers.mjs" "<repo>" --focus "<focus>" --parallel <n>` starts one headless worker per slice (`claude -p`, Sonnet, high effort, read tools plus writing under `.checks/`), each with `$SKILL/worker-prompt.md` filled in. It waits for all of them and prints one line per worker (ok / failed / timed out). Re-launch a failed or timed-out worker once with `--only <slice id>`; a second failure is reported as `NOT CHECKED: <slice>` in your summary, never hidden.
3. **Verify what the workers wrote** (a worker's "done" is a claim): `node "$SKILL/scripts/merge.mjs" "<repo>"`. It parses every `findings/*.md`, syntax-checks and runs every `scripts/*.mjs` once, marks a finding `unchecked` when its script is missing or crashes, groups findings into root causes (same rule + same place to fix + a shared specific term), writes `REPORT.md`, `causes.json` and `run-all.mjs`, and prints the counts. Open `REPORT.md` and spot-check the 3 most severe ROOT CAUSES: open the cited file:line and confirm the problem is real, and read their member findings to confirm they really are one defect (two different defects in one cause is a merge error; report it). If a finding is wrong, change its severity cell to `rejected (<why>)` in its findings file and run merge again.
4. **Refactor mode** (only when the prompt says refactor): run `node "$SKILL/scripts/refactor.mjs" <repo> --dry` and return the plan for the owner; with the owner's OK the main session runs it without --dry. refactor.mjs does its own proof (rebuild + run-all diff per cause); the coordinator only audits its report.
5. **Return** at most 15 lines: slices checked (and any NOT CHECKED), root causes by severity (and how many findings they came from), how many findings have working check scripts, the 5 most severe root causes one line each (with rule id, where to fix, pages affected), and the paths `.checks/REPORT.md`, `.checks/run-all.mjs`, `.checks/scripts/know-*.mjs`. Nothing else.

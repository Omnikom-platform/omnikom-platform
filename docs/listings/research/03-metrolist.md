# MetroList Services, Inc. (Sacramento-region MLS): IDX feed research, 2026-10-27

Read-only desk research. All pages read on 2026-10-27. Status key: CONFIRMED = read on an official MetroList page or official MetroList document; REPORTED = third-party page (vendor marketing, news, or a search-engine summary of a page); UNCONFIRMED = not found or sources conflict.

IMPORTANT WARNING: there is a second, unrelated "Metrolist" (Denver, Colorado). Several search hits about a "Metrolist IDX Technical Partner Agreement", "$25 set up + $10/month" and "100% of listings" are about DENVER and must not be applied to Sacramento. They appear in the Facts table only as a flagged exclusion.

## Summary

- Official route exists and is public on the agent side: an agent who wants MLS data on a third-party site must (a) be a MetroList Subscriber, (b) have a Subscriber Authorization Form (SAF) signed by their Responsible Broker and emailed to idxapprovals@metrolist.net, and (c) use a vendor on MetroList's "Approved IDX Vendors" list. The authorization names the website domain and the vendor, so it is per agent, per domain, per vendor. CONFIRMED.
- MetroList's rules require a written license with the MLS for IDX display (Rule 12.16(b), Rule 14.1). The vendor-side paperwork (technical partner or data license agreement) is not public on metrolist.net, and the approved-vendor page gives no way for a NEW vendor to apply. UNCONFIRMED. This is the main blocker for design: the only path is to ask idxapprovals@metrolist.net.
- Platform: MetroList's MLS system is Prospector+, "powered by Rapattoni" (CONFIRMED). IDX Broker lists the MetroList feed as type WEBAPI, vendor "Rapattoni Webapi" (REPORTED). Nothing found shows Trestle, MLS Grid or Bridge Interactive. No public API docs or endpoint names. RETS: a 2015 vendor post says MetroList served RETS Data Dictionary 1.3; current RETS status UNCONFIRMED.
- Fees are not published by MetroList. Vendors report pass-throughs: Showcase IDX $5/month (this confirms the earlier note, but it is Showcase's own figure); IDX Broker $35 data connection + $15/month data management; OSI IDX $25/month. So the "$5" is one vendor's number, not an MLS fee schedule. Reported range: $5 to $25/month plus up to $35 one-time. Per-agent vs per-site is not stated anywhere. REPORTED.
- Display rules (CONFIRMED in the MLS Rules effective 2026-06-01): refresh at least every 3 days; show the date and time the data was obtained; mandatory "All data, photos, visualizations..." disclaimer; show listing firm name and state on every display; no modification; no confidential fields; end-user Terms of Use required. No MetroList logo requirement found. The separate "IDX Guidelines" document (Rule 14.2) was not found online.
- Territory: MetroList's service area (Rule 7.8) is Amador, Butte (most), Calaveras, Colusa, El Dorado, Madera, Merced, Placer (except Tahoe Basin), Nevada, Sacramento, San Joaquin, Stanislaus, Sutter, Yolo, Yuba. Of the ten target cities only Sacramento is MetroList territory. Vacaville, Fairfield, Suisun City, Vallejo, Benicia (Solano) and Napa, American Canyon (Napa) are BAREIS territory; Concord and Walnut Creek (Contra Costa) are on the Bay East / CCAR / bridgeMLS side (exact MLS unconfirmed).
- Data share exists but is NOT proven to reach IDX feeds. MetroList members get regional access (Prospector, lockbox) to BAREIS, Bay East, CCAR, bridgeMLS, MLSListings, SFAR, Sutter-Yuba (2019 guide). A 2020 Bay East notice describes seven NorCal MLSs sharing listings in a broker-side system. Orion (Sept 2026) is MetroList + Nevada + Oregon only. Oddity: IDX Broker's MetroList feed page lists Vacaville, Fairfield, Napa, Concord, Walnut Creek and the rest as "available cities", which hints that some out-of-area listings are delivered, but delivery and IDX licensing of them is UNCONFIRMED.
- Vendors: MetroList's official 2026 list has 29 vendors including IDX Broker, iHomefinder, Showcase (plug-in), Real Geeks, Placester, Ylopo, Lofty, Luxury Presence, Sierra Interactive, Zurple, Top Producer (CRM), Diverse Solutions, OSI IDX. Brivity and SimplyRETS are NOT on it.

## Process as we understand it

1. The client agent must hold an active MetroList Subscriber login (the SAF names this a precondition). Their Responsible Broker must be an active Participant in good standing.
2. Pick a vendor from the 29 on https://mic.metrolist.net/idx-approved-vendors-2026/. Becoming a new approved vendor: path unknown; ask idxapprovals@metrolist.net.
3. The agent fills the Subscriber Authorization Form (domain, vendor, site type); the broker signs; it goes to idxapprovals@metrolist.net before the vendor serves data.
4. The vendor turns on the feed after MetroList approves. Vendors quote 2-3 business days for approval and 5-7 business days (OSI) to launch a site. MetroList states no figure.
5. The vendor passes a data fee to the agent (reported $5 to $25/month, plus up to $35 one-time).
6. The site must follow the MLS Rules: refresh at least every 3 days (vendors sync in minutes), data timestamp, disclaimer text, listing firm name and state on every listing, no edits, no confidential fields, user Terms of Use, personal non-commercial notice, and honour opted-out listings.
7. The broker stays accountable for compliance (Rule 14.1).

Design consequence for Omnikom: unless Omnikom becomes an approved vendor or builds on an approved vendor's feed, there is no documented route to raw MetroList data. Documented routes are (a) embed or plug in an approved vendor (IDX Broker, Showcase, iHomefinder, Real Geeks and others) per agent, or (b) ask idxapprovals@ about a vendor application. Nothing here can be tested without credentials, so build to an adapter interface and keep the display-rule items (timestamp, disclaimer, firm name, Terms of Use) as data-driven blocks.

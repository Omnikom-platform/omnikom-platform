# omnikom: the platform CLI (slice 1)

Spec: `docs/blueprint/26-PLATFORM-CLI.md`. One Node 20+ program, no dependencies, `psql` on the path.
`node tools/omnikom-cli/omnikom.mjs <command> [--target local|staging|production] [--as <identity>] [--expect <code>] [--json]`
Every command prints ONE JSON object `{ ok, command, target, code, expect?, matched?, exit, data }`. Exit: 0 matched, 1 not, 2 usage, 3 BLOCKED.
`--expect` takes the HTTP status (`202`) or the platform code (`S-NOT-FOUND`, `S-OWN-ONLY`, `I-UNKNOWN`...); `ok` is the success code of SQL commands.
Targets read variables by NAME: `STAGING_DB_URL STAGING_SUPABASE_REF ..._SECRET_KEY ..._PUBLISHABLE_KEY`, the `PROD_` set, `LOCAL_DB_URL` (this machine only), `LOCAL_FUNCTIONS_BASE`. Default target: local.
Secrets never leave the program: stdout and stderr pass `lib/redact.mjs`; psql gets its connection through `PG*` variables, never argv.

It never touches this checkout's working tree, index or local `master`, and says whether the local master contains the commit. No target |

A pre-push hook that is not ours is never overwritten or removed (exit 3); with `core.hooksPath` set, install is refused (exit 3) |
| `hooks pre-push` | what git runs, by the REMOTE ref: `refs/heads/check/**` allowed (create, update, delete); `refs/heads/master` only a fast-forward (the remote master must be an ancestor and be in this clone) to a commit whose public copy (DECISIONS 46) had a `ci` run on GitHub with every `ci.yml` job green (the copy commit is computed from the pushed commit; read with `gh`; no `gh` answer is a refusal, fail closed; a delete is refused); any other ref (another branch, a tag) is refused. There is no prose exception: the impact graph has known gaps, so it cannot be the judge. **`git push --no-verify` skips every hook. It is the owner's alone: no session, head or builder uses it** (every refusal ends with that line) |
| `copy build <sha\|ref> [--dry-run]` / `copy push check/<department>/<slug> [--remote <name>] [--json]` | the public, code-only copy that runs CI (DECISIONS 46, see "The public copy" below). No target. `build` makes the copy of a private commit and runs the gate over it, in this repository's object store only: it prints `copy: <private sha> -> <copy sha> (<n> files, <m> dropped, <k> transformed)`, the copy tree, `gate PASS` or the refusal; nothing is pushed (`--dry-run` says so; `--rules <file>` tries rules that are not committed yet and is for `--dry-run` only). `push` reads the private branch's sha from the private remote (as `land` does), builds and gates the copy and pushes it to the SAME branch name of the public repository, then prints the public run url once GitHub lists it. Exit 0 ok, 1 the gate refused (`COPY-REFUSED`), 2 usage, 3 blocked |

Fixtures live in `fixtures/` and are synthetic (example.com, 555); anything else needs `--real` and prints a warning.

## Impact, the GitHub gate and the pre-push hook (DECISIONS 43, amended by 45)
Why: platform 4.6 changed the test contract in `supabase/tests/tenancy.test.sql`; the CLI fix changed `commands/seed.mjs`, which `supabase/functions/test/harness.mjs` reads; each push ran only its own department's tests and CI went red. Now the chain is found before the commit by a tool, and a push of an untested tree is refused.
- **The graph** (`lib/graph.mjs`, from `git ls-files`; for `--commit` and the hook, from that commit's tree). Only `.mjs .js .cjs .ts .sql .yml .yaml .json .sh .ps1 .toml` are read; every other file is a leaf. An **import edge** is a static `import ... from`, `export ... from`, `import()`, `require()` with a relative specifier; it is followed transitively. A **read edge** is a path built from string literals in one call (`join`, `resolve`, `path.join`, `new URL('<p>', import.meta.url)`, `repoPath`, `importRepo`) or a bare string literal with a `/` that names a tracked file; it is one step only. A first argument `REPO`, `REPO_ROOT`, `ROOT`, `root` or `repoRoot` counts from the repository root, any other first argument from the file's folder or the nearest parent folder where the path exists. A **folder** counts as read (every file under it) only when it is written as a bare literal or built from the root, and has at least two path segments. Comments and regex literals are skipped by the tokenizer. YAML, shell and TOML files count by the path tokens in them (a glob is an entry point's business only). The entry points are each `ci.yml` job's `run:` lines and each row of the `GATES` table of `run-all-gates.mjs` (read as data; the secret scan job covers every file and is never printed). A gate or job covers a file when it is in the import closure of its entry files or is read (one step) by a code file in that closure.
- **Named copies**: `impact-copies.json`, a list of `{ name, files, why }`. A change to one file of an entry lists the others as `copy NAME of <file>`. A unit test fails when a listed file no longer exists. Entries today: TEST_CONTRACT and TEST_IDENTITIES (`seed.mjs`, `identity.mjs` and `tenancy.test.sql`), PUBLISH_REQUIRED (`contracts/validate.mjs` and the SQL port in migration 11), TOOL_PINS (`ci.yml` and `tools.json`), CAPTURE_LEAD_MODEL (the function and the CLI harness's model of it). Add a copy here the day one is made.
- **Owner**: the charters' `## Owns` lists (`docs/departments/*.md`); the longest matching path wins and a bullet's `except` paths are not its own. A file nobody owns prints `unowned` and a `finding:` line.
- **The gate is the GitHub run** (DECISIONS 45; `lib/ghrun.mjs`). There are no local stamp files. A head commits, pushes the commit to `check/<department>/<slug>` on `backup-gh` (ci.yml runs on every push), and `omnikom land` moves master only to a commit whose run was green. `ciVerdict` runs `gh run list --repo <owner/name> --commit <sha> --workflow ci.yml --json ...`, keeps only runs whose `headSha` is exactly the commit, ignores `cancelled` runs, and reads each completed run's jobs with `gh run view <id> --json jobs`. `none`: no run left. `pending`: any kept run not completed. `red`: any completed run whose own conclusion or any job's conclusion is not `success` (skipped counts as not green), or that lacks a job whose `name:` is in `ci.yml` at that commit; one green run beside a red run of the same sha is red (re-run the job on GitHub to fix a flake). `green`: at least one completed run and none red. A failing `gh` (not installed, not logged in, offline) is BLOCKED, and the hook and land fail closed. The repository is parsed from the remote url (github.com, https or ssh); a test names it through `deps.ghRepo`, never an environment variable.
- **The landing queue** (`commands/land.mjs`, the name in `lib/landlock.mjs`): `refs/heads/land-lock` on the remote, so that two heads never both move master. `land` takes it first, before the ci wait, by pushing (plain `git push <remote> <lock>:refs/heads/land-lock`, no force) a ROOT commit of the empty tree whose message is `land-lock: <branch> <sha> by <department> (<git user.name>@<hostname>) at <ISO time>`; a root commit is never a fast-forward of another root, so git refuses a second creator and that refusal is the lock. A lock held by someone else: `LAND-LOCKED` (exit 1), `land: <holder> holds the land lock since <time> (<n> min) for <branch>`, nothing else happens. A lock whose committer date is more than 90 minutes old is stale: `land: breaking a stale land lock held by <holder> since <time> (<n> min)`, deleted with `git push --force-with-lease=refs/heads/land-lock:<its sha> <remote> :refs/heads/land-lock`, then taken. The lock is released after the fast-forward and on EVERY refusal or BLOCKED after it was taken, with the same lease on OUR lock's sha (a lock broken and retaken by someone else is never deleted by its old owner); `land: lock released`, or a warning with the manual command when the release fails (a failed release never turns a successful land into a failure). `--force-with-lease` is used for the lock delete only; the master push is plain. The pre-push hook allows `refs/heads/land-lock` (`pre-push: refs/heads/land-lock is the land queue, allowed`). Dates come from `ctx.now`. ci.yml must not run on pushes of the lock: its `push:` has `branches-ignore: [land-lock]` (a unit check reads the real file).
- **The CLI full suite on GitHub** (`test/ci-heavy.mjs`, one `ci.yml` step in the `cli` job): the unit run stays on every push; `test/run.mjs` and then `test/mutate.mjs` run only when the change can reach them: a changed file under `tools/omnikom-cli/`, `.github/workflows/ci.yml`, or a file `omnikom impact` says the `cli` job reaches (seed.mjs, tenancy.test.sql, apply-staging.mjs, whatever the graph sees). The base is `$OMNIKOM_CI_BASE`, else the merge base with `refs/remotes/origin/master`, then `refs/remotes/backup-gh/master`; no base means run (fail safe). On master the diff is empty, so it skips. Prints `ci-heavy: needed (<first 5 files>)` or `ci-heavy: not needed (<n> changed files, none read by the CLI suite)`; the exit code is the first failing child's.
- **The cluster guard** (`test/harness.mjs`): every throwaway Postgres cluster records `{ pid, dir, data, port }` in a marker file under `<os tmp>/omnikom-cli-clusters/`. A normal exit and SIGINT / SIGTERM / SIGBREAK stop it and delete the marker; a hard kill runs no handler on Windows, so `startCluster` first sweeps: every cluster whose owning process is dead gets `pg_ctl stop -m immediate`, its folder (only one made by the guard, inside the temp folder) and its marker removed; a live owner is left alone. The unit part tests this with a fake pg_ctl and planted markers; the real kill test (a child starts a cluster, is killed, the sweep stops it) is in the db part. The CLI tests start no browser.
- **The checkout for reproducing a failure**: `ci --staged | --commit <sha> [--job <id>]` runs on `git write-tree` of the index (or a commit's tree) in a checkout under `D:/omk-gates` (one constant in `lib/checkout.mjs`; E: is nearly full and a path containing "claude" is refused by a local guard; tests pass another root through `ctx.gatesRoot`). It is removed afterwards, also on failure.
- **The hook**: `omnikom hooks install` in the repository the owner chooses; it is installed by the head, never by a builder, and never in a repository a test did not create. The shim says `(DECISIONS 45)`. A refusal of master reads `pre-push: REFUSED refs/heads/master: <sha> has no green ci run on the public copy <copy sha> (<public repo>); push it to check/<department>/<slug>, run: node tools/omnikom-cli/omnikom.mjs copy push check/<department>/<slug>, then: node tools/omnikom-cli/omnikom.mjs land check/<department>/<slug>`, then the verdict lines (`<run url>  <job name>  <conclusion>`), then the `--no-verify` line.
- **What the graph cannot see (known gaps)**: a path assembled at run time from a variable (`join(dir, name)`), an import map or alias, a path read out of a data file, a command run through a shell string, a glob built in code, and the `deno task check` step of `run-all-gates.mjs` (not a row of `GATES`). A bare literal that is only an example (a `--owns tools/omnikom-cli/` argument in a test) counts as a read: the graph errs towards naming a gate that is not needed, never towards missing one that is.

## The public copy (DECISIONS 46)
Why: the private org repository has no Actions minutes left; a public repository under the owner's account runs Actions free, but the private repository holds client material. So CI runs on a **code-only copy**, and `land` and the pre-push hook read the copy's verdict. The copy holds no history and no secrets.
- **The rules** are one file, `public-copy.json`, read from the private commit being copied (so the same commit always gives the same copy): `deny` (path prefixes; matched without regard to case), `why`, `workflowsKept` (every other file under `.github/workflows/` is dropped: they use secrets and some run on a schedule), `denyNamed` (every other file that names a client: slug, business or person; DECISIONS 47; a file leaves the list when its owner has anonymised it), `jobsNotOnCopy` (job id to `{ reason, files }`: the denied files that keep the job off the copy; the job is removed from the copy's `ci.yml` and `land` runs it on the laptop), and `repo` (the public repository, owner/name). The file goes into the copy, so it never names a client.
- **The copy** (`lib/copy.mjs`, git plumbing only, never the working tree): `git ls-tree -r`, `git mktree`, `git hash-object -w` for the transformed `ci.yml`. It is a ROOT commit of that tree; author, committer and both dates are the private commit's; the message is `copy of <sha>`, a blank line, then `Private-Commit`, `Private-Tree` and `Copy-Rules` (sha256 of the rules file). Same input, same commit.
- **The gate** (`checkCopy`, `COPY-REFUSED`, exit 1, every offending path printed, nothing pushed): (1) a path of the built tree under a denied prefix (the tree is read back with `git ls-tree -r`, independent of how it was built); (2) a file, or a path, that names a client: the names come at run time from the PRIVATE commit's `clients/` folder only: every folder slug except `TEMPLATE` and `test` (sorted), plus the business name and the person names in the H1 of that folder's `profile.md` (`# <business> (<person>, <person>): profile`). A name matches only as a whole word (not inside a longer run of letters or digits), without regard to case, in every text blob (a NUL byte in the first 8 KB makes it binary and skipped). The output is `<path>:<line> names client <n>`, `n` being the slug's index: a client's name is never printed, and a path that holds one is printed with that segment as `[client <n>]`; (3) `gitleaks detect --no-git --redact` over the copy's files in a temp folder (removed on every path; the binary comes from `ctx`, `.tools/bin` or the pinned download of `tools.json`, never PATH or an environment variable); (4) the copy's `ci.yml` must parse with `parseJobs` and `parseWorkflow`, `jobsNotOnCopy` may name only jobs the private `ci.yml` has, none may remain, and no remaining job may `need` one.
- **The push** (`omnikom copy push`): from a TEMPORARY BARE repository that borrows this clone's objects (`objects/info/alternates`) with hooks switched off, so this clone's pre-push hook (which is for the private repository) never sees it and no ref of this clone changes. A `check/**` branch is force-replaced (a root commit is never a fast-forward); the public `master` is replaced only with a `--force-with-lease` on the tip just read; nothing else is ever written. Same private sha: same copy commit, "already is", nothing pushed.
- **Jobs that run on the laptop** (DECISIONS 47): a `ci.yml` job that cannot run without denied files is listed in `jobsNotOnCopy` with those files. The gate checks that every listed file is denied and every listed job is a job of the private `ci.yml`. `land` runs each listed job, after the copy's run is green and before master is touched, for the exact private sha, through `~/.claude/scripts/heavy.mjs` (`omnikom ci --commit <sha> --job <id>`), and refuses unless each passes (`LAND-REFUSED` naming the job). The report says `<job>: laptop, not GitHub (DECISIONS 47): PASS|FAIL`. The pre-push hook cannot see a laptop run: master is reached through `land`. A job leaves the list when its files are clean and the copy runs it green.
- **`land`**: the public repository's branch of the same name must exist, its tip's TREE must equal the expected copy tree and its message must carry `Private-Commit: <that sha>` (else Blocked, "run omnikom copy push"). The verdict is the PUBLIC repository's run of that tip, with the job names of the copy's `ci.yml`. The output says `verdict from <repo> run <id> of copy <sha>` and lists `not run on the copy (DECISIONS 46): <job>: <reason>`. After the private master moved, the copy of the new master replaces the public `master`; a failure there is a warning, not a failed land. The public `master` is the only ref ever force-replaced with a lease, because each copy is a new root commit and has no history (DECISIONS 46 (a)); the private repository is never forced.
- **The hook**: for a push to the private master the copy commit is COMPUTED from the pushed commit (it is a function of it), and its run is read; a run of any other tree is another commit. No rules file, no public repository, no `gh` answer: refused.

## How ci maps ci.yml
ci.yml is read by a small reader for this file's shape (`parseWorkflow` in `commands/ci.mjs`; no YAML dependency). Every step is mapped BY NAME in the table `ROWS` to its local action:
- `uses: actions/checkout` is "the working tree" (the line says so); `setup-node` and `setup-deno` are a version check (`node --version`, `.tools/bin/deno --version`) against ci.yml's and the manifest's version.
- the PostgreSQL PATH step is "`initdb` found" (it must be on the PATH, as the CLI's own tests need it); the `df` steps report disk and memory.
- `run: node ...` steps run the same command line through the running node (one command line, no shell syntax: a `&&` or a pipe in such a step FAILs the job instead of being half-run).
- `curl ... sha256sum ... tar` download steps become `tools ensure --only <tool>`, after checking that the step's version, url and sha256 equal the manifest's linux entry; the later `"$RUNNER_TEMP/<tool>/<tool>"` call becomes `.tools/bin/<tool>` with the same arguments (a glob like `.github/workflows/*.yml` is expanded by the runner, sorted). actionlint always gets `-shellcheck .tools/bin/shellcheck` given explicitly (before the file arguments), the shellcheck version is checked against the manifest, and the job's line ends with `[shellcheck <version>]`.
- `npm ci ...` runs as written only with `--install`; without it the step is SKIP (PASS) when `factory/runner/node_modules` exists and FAIL ("run with --install") when it does not.
- A step the table does not map, a step key the reader does not model (`env:`, `shell:`, `continue-on-error:`...), an `if:` other than `always()`, a job key other than name, runs-on, timeout-minutes and steps, or a top-level key other than name, on, permissions, concurrency and jobs, FAILs: ci.yml cannot grow a check this command skips. A rename of a mapped step is the same failure on purpose (the platform department then updates the table here).
- A step after a failed step is SKIP unless it has `if: always()`. Each command gets the job's `timeout-minutes` as its time limit, never less.
- stdout and stderr are captured separately: a failing command's last line is the last line of its stderr when it printed any.

## Tests
`tools.json` and ci.yml agree (a test with its own regular expressions fails when a version, linux url, sha256, `node-version` or `deno-version` differs); `tools ensure` and `ci` are tested over a fake fetch and fixture archives built with the system tar, with a fake spawn that records the tools' calls: no network and no real download. The real ci.yml is run through `ci --install` with every command faked, to prove that every step of it is mapped today.
`node tools/omnikom-cli/test/run.mjs [--unit|--db]` (units + a throwaway cluster; the cluster takes minutes to start on this machine) and `node tools/omnikom-cli/test/mutate.mjs` (one rule removed per mutant, all must go red).

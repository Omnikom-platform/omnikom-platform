# SE-001 (P0, search-engines)

Source: checklist/search-engines.md SE-001 (skill checklist copy: "robots.txt health (Google treats server errors on robots.txt as a full
disallow for a period; Naver treats 5xx as "disallow everything")"); the parts below come from the slice 2 brief, which cites the shipgate
spec 8.0.0, pack file `shipgate/spec/packs/search-engines.md`, read 2026-10-30.
Check: `checks/se-001.mjs`. Fixtures: `fixtures/snapshot-bad-SE-001*`.

## Rule text
robots.txt health: status 200 (a 404 is the part `missing`, a WARN), never 5xx or 429, content type `text/plain`, at most 512,000 bytes,
valid UTF-8.

## Judged here (snapshot mode; the HTTP facts are in `site/robots.json`, the body in `site/robots.txt`)
- status: 200 passes. 404 is a WARN `missing-element` (crawlers read it as no restrictions; IDX-004 fails the same fact as a missing file).
  5xx and 429 are a FAIL `status-mismatch` (Google and Naver treat them as "disallow everything"). Any other status, or a fetch error with no
  status, is a FAIL `status-mismatch`. A non-200 snapshot saves no body, so nothing else is judged then.
- content type: the `content-type` header must start with `text/plain` (any case, any parameters). Else FAIL `value-mismatch`.
- size: `robots.json.bytes`, the size the server sent, at most 512,000. The saved file is cut at 190 KB by the snapshot, so it is not the measure.
- UTF-8: the saved bytes are decoded with `fatal: true`; a throw is a FAIL at the first bad line. A U+FFFD in the saved text is the same FAIL:
  `snapshot-site.mjs` writes the body with `toString("utf8")`, which replaces a bad byte with U+FFFD before the file is saved.

## Judged here (folder mode)
Only the size and the encoding of the `robots.txt` file. A folder with no `robots.txt` is a SKIP (IDX-004 reports the missing file).

## Not judged here
Status and content type in folder mode (needs a fetch; listed in the check's `notCovered`).

# SEC-075 (P1, CSP strength)

Source: checklist/security.md SEC-075 (skill checklist copy, the id and a cut-short text); full text from the shipgate spec 8.0.0,
pack file `shipgate/spec/packs/security.md` line 92, read 2026-11-10 (work order 38, row E7 of the product book); OWASP CSP Cheat Sheet and ASVS 5.0 V3 as the spec names them.
Check: `checks/sec-075.mjs`, readers in `lib/secheaders.mjs`, hosts in `lib/csp-bypass-hosts.json`. Fixtures: `fixtures/bad-SEC-075*`.

## Rule text
CSP strength, on the same responses whose `Content-Security-Policy` SEC-010 judges, when `csp.required`; otherwise `notApplicable`.
`Content-Security-Policy-Report-Only` is ignored; with several enforced CSP headers a condition is met when any one of them meets it. Script sources = the `script-src`
directive, else `default-src`. Main part (P1): (a) when the script sources contain `'strict-dynamic'` together with a `'nonce-...'` or hash source, host and scheme
sources are ignored (CSP Level 3) and (b) is skipped; (b) otherwise the script sources contain no `*`, no scheme-only source (`https:`, `http:`, `data:`, `blob:`),
no host source with `*` in its registrable-domain part (Public Suffix List), and no host source whose host is in the ruleset `csp-bypass-hosts.json`
(`[{ host, reason }]`: hosts serving JSONP endpoints or script gadgets such as AngularJS, e.g. `www.google.com`, `ajax.googleapis.com`, `cdnjs.cloudflare.com`,
`cdn.jsdelivr.net`, `unpkg.com`; matched by exact host); (c) the script sources contain no `'unsafe-eval'` unless `csp.allowUnsafeEval: true` (`'wasm-unsafe-eval'`
is allowed); (d) `object-src` is `'none'`, or there is no `object-src` and `default-src` is `'none'`; (e) `base-uri` is present with the value `'self'` or `'none'`.
Part `form-action` (W): `form-action` is present. Findings `header-value` showing the URL, the directive and the offending source (or the missing directive).
A judged response with no enforced `Content-Security-Policy` header gives no SEC-075 finding (SEC-010 reports the absence).

## Judged here
- The same pages and the same header sources as SEC-010 (a snapshot's saved response headers; a folder's `_headers` file).
- (a) to (e) and form-action as written above. Each failed condition is one FAIL (form-action: one WARN) naming the page, the offending source or directive and the
  header's origin.
- No script-src and no default-src is a (b) finding: scripts are then not restricted at all (the spec's text does not name this case; it follows from "script sources").
- The bypass list holds the five hosts the spec names, with a reason each; it is the ruleset file, so it grows without a code change.

## Not judged here
- The registrable domain is read without the Public Suffix List (no dependency allowed): a wildcard host source is refused when it is not a leading `*.`, when fewer than two
  labels follow it, or when what follows is one of 14 two-label suffixes (co.uk, com.au, ...). A wildcard under a suffix not in that list (UNPROVEN) is accepted.
- Directives other than script-src, default-src, object-src, base-uri and form-action: a wildcard in `connect-src` or `img-src` (the dashboard's `https://*.supabase.co`)
  is not a finding here, and the spec's payment-page split with SEC-063 does not apply.
- Hosts of the bypass list are matched by exact host only (as the spec says); a subdomain or a path form of a listed host that differs is not caught.
- A page with no enforced policy, and every page when `csp.required` is false.

# DSN-002 (P1, design tells): gradient text and hue gradients

Source: skills/unslop/references/signs.md:7-8 and skills/unslop/SKILL.md:89; planning/DECISIONS.md 37 (owner, 2026-10-31); unslop by Damir Sokolovsky, CC BY 4.0
Check: `checks/dsn-002.mjs`. Fixtures (folders under `fixtures/`): bad-DSN-002-text, bad-DSN-002-text-css, bad-DSN-002-background, bad-DSN-002-background-css, bad-DSN-002-background-stylesheet, and bad-DSN (every tell on one page).
This rule is DECISIONS 37's list of design tells made into a check; the list comes from the open skill unslop by Damir Sokolovsky
(github.com/heydamir/unslop, folder skills/unslop, CC BY 4.0). The rule text below is written for this engine in our own words.
Severity P1; the verdict of each finding is FAIL. A finding names the rule, the page, the line, the exact text or class that tripped it, and the source.

## Rule text
A page has no gradient text and no hue gradient as a background.
- Text: an element with both `bg-clip-text` and `text-transparent` classes fails; so does an element that declares `background-clip: text`
  (or `-webkit-background-clip: text`) and also has a gradient (a CSS `linear-`, `radial-`, `conic-gradient` in `background` or `background-image`,
  or a Tailwind class `bg-gradient-*`, `bg-linear-*`, `bg-radial*`, `bg-conic*`).
- Background, Tailwind: the `from-`, `via-` and `to-` colour classes of one element, taken per variant group (the unprefixed ones together,
  `dark:` ones together), that name two different hue families fail. `from-indigo-500 to-purple-600` fails; `from-blue-500 to-blue-800`,
  `from-slate-100 to-white` and `from-red-500 to-transparent` pass.
- Background, CSS: a `linear-gradient`, `radial-gradient` or `conic-gradient` (also `repeating-`) in `background` or `background-image` whose
  colour stops parse to two different hue families fails. A scrim from black to transparent passes.
Greys, black, white and transparent are no family, so a colour with a grey tint never makes a hue gradient.

## Judged here
Both parts above. The hue-family table below is the head's reading of DECISIONS 37 ("hue gradients as backgrounds"): a family is a range
of the hue angle (HSL) of a colour, and each Tailwind colour name belongs to one family. A colour is no family (grey) when its HSL
saturation is under 0.1, its lightness under 0.05 or over 0.96. Black, white, transparent, currentcolor and the Tailwind greys (slate, gray, zinc, neutral, stone) are no family.

| family | hue angle in degrees | Tailwind colour names |
|---|---|---|
| red | 345 to 15 | red, rose |
| orange | 15 to 45 | orange |
| yellow | 45 to 75 | amber, yellow |
| green | 75 to 165 | lime, green, emerald |
| cyan | 165 to 195 | teal, cyan |
| blue | 195 to 255 | sky, blue, indigo |
| purple | 255 to 315 | violet, purple, fuchsia |
| pink | 315 to 345 | pink |

Where the styles come from: the element's `class` and `style` attributes, the page's `<style>` blocks, and, in a built folder only, the
local stylesheets the page links (`<link rel="stylesheet" href>` that resolves to a file inside the folder). A stylesheet or `<style>`
selector is matched only when it is one plain class (`.card`) or one element name (`h2`), alone or in a comma list; a selector with a
combinator, a pseudo-class, an attribute, an id or a compound part is not judged. Order used: element rules, then class rules, then
Tailwind classes, then the style attribute; a later declaration of the same property wins. Specificity, media queries and inheritance
are not computed: the engine sees declared styles, not computed ones. A stylesheet's `@import` is not followed, and rules inside `@media`,
`@supports` and `@layer` are read as if they always applied.

## Not judged here
Colour stops written as `oklch()`, `oklab()`, `lab()`, `lch()`, `hwb()`, `color()`, `color-mix()` or `var()` are not read, nor are Tailwind
colour names outside the default palette (a custom `from-brand`): a gradient is judged on the stops that can be read. Gradients drawn
by JavaScript or in an image. Gradients on pseudo-elements. A snapshot (a live site saved by the skill's snapshot script) carries each page's HTML only, so in a snapshot this rule judges what the
HTML carries (classes, style attributes, `<style>` blocks, text); the site's stylesheets are not in the snapshot and are not judged.

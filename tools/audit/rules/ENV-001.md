# ENV-001 (P0, build target)

Source: factory/lib/launch.mjs headersText and factory/README.md (robots.txt always Allow, the preview kept out by X-Robots-Tag; head, 2026-10-31); head of operations, 2026-11-01 (slice 4c)
Check: `checks/env-001.mjs`. Fixtures: `fixtures/bad-ENV-001-*`, `fixtures/good-preview`, `fixtures/snapshot-bad-IDX-001-header`.

This rule is not a line of the shipgate checklist: it is the department's own rule, written for the Omnikom factory. The factory keeps a preview out of the
index on purpose, with the response header `X-Robots-Tag: noindex, nofollow` on every path (`headersText({ preview: true })` writes `/*` and that line into
`_headers`), while `robots.txt` always says `Allow: /` (so IDX-004 judges the same file in both builds). The first real live run (2026-11-01) audited a
preview that answered `x-robots-tag: noindex` on every page and no rule saw it, because `page.noindex` was read from the meta robots tag only. A production
site hidden by that header would have passed every rule.

## Rule text
The build's indexing matches its target. The target is given with the audit (`audit(dir, { target })`, `run.mjs --target preview|production`,
`live.mjs --target ...`), with no default.
- target `preview`: every HTML page carries noindex, in the `X-Robots-Tag` header or in a meta robots tag. Each page that does not is one FAIL ("a preview would be indexed").
- target `production`: no HTML page carries an `X-Robots-Tag` noindex header. Each page that does is one FAIL. A meta robots noindex on a page is not this rule's
  business (a deliberately unlisted page; IDX-001 judges it against the sitemap).
- Every finding names the page, where the noindex comes from (the `_headers` file with its pattern and line, or the response header), and the target.

## Judged here
- Folder mode: the `_headers` file at the root of the folder (Cloudflare Pages format: a path pattern at column 0, then indented `Name: value` lines; `*` is a splat,
  `:name` a placeholder that matches one path segment, `! Name` detaches a header set by an earlier matching rule). Each built page is matched at the path it is
  served at (`about/index.html` is `/about/`, `index.html` is `/`, `foo.html` is `/foo`), case-sensitively, rules in file order. Each matching rule's
  `X-Robots-Tag` line counts as its own header line.
- Snapshot mode: the `x-robots-tag` header saved in each page's `response.json` (any case of the name; several values, or an array, count).
- Which values count: a value with no bot name in front of it, or after `googlebot:`; a value for another named bot (`bingbot:`, `googlebot-news:`) does not.
  A bot name holds until the next bot name in the same line. `none` counts as noindex. `unavailable_after` and the `max-*` directives are not bot names.

## Not judged here
- With no target: a run prints one `SKIP ENV-001 / no --target ...` line (the site-wide subject `/`, in folder mode and in snapshot mode; no PASS and no FAIL line) and
  judges no indexing. A check that did not run is never silent (head of operations, 2026-11-01, final). `REQUIRE_TARGET_FOR_FOLDER` in `index.mjs` is the one-line
  switch that later turns "no target for a folder" into a usage error (exit 2); a snapshot is never refused. Until the factory and the CLI pass a target the SKIP stays. The other rules then behave as before: a snapshot's header noindex feeds
  `page.noindex` (it is what the live site says); a folder's `_headers` is ignored.
- A `_headers` pattern that cannot be matched exactly is not judged: a pattern that is not a path (a host pattern such as `https://:project.pages.dev/*`; the
  audit does not know the host) and a pattern with more than one splat. A preview finding names such patterns, so a reader sees what was not judged.
- A built folder's root `404.html` (a 404 page is out of scope here), and in a snapshot every record that did not answer 200.
- Whether Cloudflare joins several `X-Robots-Tag` lines of different rules into one value or sends them as lines is not known to this check (UNPROVEN); it reads each
  line on its own, which matters only for a bot name that would hold across two rules.
- The meta tag `<meta name="googlebot">` is not read (neither before this slice).

## What the target changes for the other rules
- `production`: a header noindex feeds `page.noindex`, so IDX-001 (and every rule that skips pages that are not indexable) judges what Google will see.
- `preview`: the header noindex is expected and does not feed `page.noindex`; the other rules judge the site as it will be in production. A meta robots noindex always feeds.
- no target: a snapshot feeds the header into `page.noindex`; a built folder ignores `_headers`. ENV-001 itself prints the one SKIP line and judges nothing.

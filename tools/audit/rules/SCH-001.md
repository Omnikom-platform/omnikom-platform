## Rule text
One `<script type="application/ld+json">` per page with `@graph`; it parses; it contains a `WebPage` node (or subtype: AboutPage, ContactPage,
CollectionPage, FAQPage, ItemPage, ProfilePage, SearchResultsPage) whose `@id` is `{canonical}#webpage` and a `WebSite` node or `@id` reference
`{origin}/#website`; the home page (`/`) carries the full `Organization` node `{origin}/#organization` (other pages may reference it by `@id`);
every `@id` reference in the block resolves to a node in the same block or, for the organization and website ids, in the home page's block.
A second ld+json block is duplicate-element; a parse error is a FAIL naming the JSON error.

## Judged here
- one block (none: missing-element; a second: duplicate-element), it parses (the FAIL carries the JSON error), it has an `@graph` array.
- a WebPage-type node with `@id` equal to `{canonical}#webpage` (when the page has no canonical the id comparison is left to URL-009).
- `{origin}/#website` as a WebSite node or an `@id` reference; `{origin}` is the origin of the home page's canonical (else the first
  canonical found), because a folder has no host.
- the home page's Organization node with a type and a name; every pure `@id` reference resolves in the block, or in the home block for the
  website and organization ids.

## Not judged here
Nothing of this rule is left out. (Schema.org property validity is not part of this rule.)

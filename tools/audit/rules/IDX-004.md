# IDX-004 (P0, web-delivery)

Source: checklist/web-delivery.md IDX-004 (skill checklist copy, the id and a cut-short text); full text from the shipgate spec 8.0.0,
pack file `shipgate/spec/packs/web-delivery.md`, read 2026-10-30 and pasted from the slice 1 brief.
Check: `checks/idx-004.mjs`. Fixtures: `fixtures/bad-IDX-004*`.

## Rule text
robots.txt: present at the folder root, references the sitemap (`Sitemap:` line whose path is the sitemap file), never disallows a sitemap
URL or any indexable page of the folder. (The HTTP parts, 200 and text/plain, are slice 2's and are SKIP here.)

## Judged here
- `robots.txt` exists at the folder root (else missing-element).
- a `Sitemap:` line exists and one of them has the path of the folder's root sitemap file.
- for the groups of `*`, `googlebot` and `bingbot`: no winning `Disallow` (longest matching pattern, `Allow` wins a tie, `*` and `$`
  understood) for any indexable page path or any sitemap file path.

## Not judged here
The HTTP parts: status 200 and content type text/plain of the production robots.txt. They are in the check's `notCovered`, not printed as
SKIP lines, so that a clean site prints only PASS lines (slice 2 adds them).

## Snapshot mode (slice 2)
- robots.txt is `site/robots.txt` with `site/robots.json` `{ status, headers, bytes }`. The HTTP parts are judged here: `status` must be 200
  (else one FAIL `status-mismatch`; a non-200 saves no body, so nothing else is judged then), and the `content-type` header must start with
  `text/plain` (else FAIL `value-mismatch`). SE-001 judges the same two facts, so one broken header gives both rules a finding.
- The `Sitemap:` line is compared with the URL path the root sitemap was fetched from (`site/sitemaps.json` `fetched[].url`), not with the
  saved file name. Sitemap paths in the Disallow test are those URL paths.
- In folder mode these two HTTP parts stay in the check's `notCovered`.

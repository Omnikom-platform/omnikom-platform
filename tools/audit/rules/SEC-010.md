# SEC-010 (P1, security headers)

Source: checklist/security.md SEC-010 (skill checklist copy, the id and a cut-short text); full text from the shipgate spec 8.0.0,
pack file `shipgate/spec/packs/security.md` line 91, read 2026-11-10 (work order 38, row E7 of the product book).
Check: `checks/sec-010.mjs`, readers in `lib/secheaders.mjs`. Fixtures: `fixtures/bad-SEC-010*`, `fixtures/snapshot-bad-SEC-010*`.

## Rule text
Every 2xx `text/html` response of sampled pages sends: `Content-Security-Policy` (when `csp.required`; otherwise that header check is `notApplicable`) whose
`script-src` (else `default-src`) contains no `'unsafe-inline'` unless it also contains a `'nonce-...'` or `'sha256-...'`/`'sha384-...'`/`'sha512-...'` source or
`csp.allowUnsafeInlineScripts: true`, and which contains a `frame-ancestors` directive (any value); `X-Content-Type-Options: nosniff`; `Referrer-Policy` whose last
valid token is one of `no-referrer`, `same-origin`, `strict-origin`, `strict-origin-when-cross-origin`; `Permissions-Policy` present and parsing as an RFC 8941
dictionary. The finding names the URL, the header and the actual value. Part `hsts` (P1): `Strict-Transport-Security` with `max-age` of at least 31536000.
Part `isolation` (W) and part `trusted-types` (W) are in the spec and not built here. (CSP source strength: SEC-075; a response with no enforced CSP is reported here,
never by SEC-075.)

## Judged here
- Snapshot mode: the headers saved in each page's `response.json` (`headers`, every response header, kept by `snapshot-site.mjs`; any case of the name; a value that
  is an array counts as several lines). Only pages that answered 200 (the engine's own page list).
- Folder mode: the headers the folder's `_headers` file (Cloudflare Pages format, see ENV-001) gives each built page at the path it is served at; each matching rule's
  line is its own header line, `! Name` detaches. A folder with a `_headers` file is judged on every page except the root `404.html`.
- Several `Content-Security-Policy` lines (or a value with commas) are several enforced policies; a condition is met when any one policy meets it (the spec's
  words for SEC-075, used here too). `Content-Security-Policy-Report-Only` does not enforce: when only that header is sent the finding says so.
- `csp.required` (default true), `csp.allowUnsafeInlineScripts` and `csp.allowUnsafeEval` come from the spec's config block; they are set in `options.config` or in an
  `audit.config.json` in the folder; a value that is not true or false is exit 2.
- Interpretation, said here so it is not hidden: the spec judges `Strict-Transport-Security` only when present on the crawl responses and requires it on the edge
  HEAD of each origin. A snapshot of a live site and a `_headers` file are the origin's own answer, so both are judged as the edge half: absent is a FAIL.
  `X-Frame-Options` is not a condition (frame-ancestors is); the dashboard sends both.

## Not judged here
- A folder with no `_headers` file: the host may add the headers, so the folder says nothing, and the rule prints no line for it (no SKIP: a SKIP line is a
  site-wide count that would change every folder run; the head of operations decides whether it should print one).
- The isolation part (COOP, COEP, CORP) and the trusted-types part, both W in the spec.
- A `_headers` pattern that cannot be matched exactly (a host pattern, more than one splat): its headers are not applied, and a finding names the pattern.
- A header added after the folder is built (a Pages Function, an edge rule): `_headers` does not reach Functions (Cloudflare docs, read 2026-11-10).
- The meta tag form of CSP (`<meta http-equiv>`): it cannot carry `frame-ancestors`, and the spec asks for the header.

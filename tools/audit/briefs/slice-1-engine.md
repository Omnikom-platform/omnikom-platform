# Brief: audit engine slice 1, `tools/audit/` over a built site folder (Sonnet builder; one slice, one brief, discarded when done)

Department: SEO and audits (`docs/departments/seo-and-audits.md`). You report to the head of this department (the session that

## What you build
A dependency-free Node library (Node built-ins only, ES modules, `.mjs`) plus a runner that audits a folder of built static HTML
against the shipgate checklist rules listed below, one check per rule id. Files, all under `tools/audit/`:

| File | What it is |
|---|---|
| `lib/site.mjs` | the site reader: a copy of `skills/programmatic-enterprise-web-performance/scripts/lib-site.mjs` (`parseHtml`, `normPath`, `resolveInternal`, `loadSite`) and the few helpers it imports from `lib-text.mjs` (`words`). First line: `// Copied from skills/programmatic-enterprise-web-performance/scripts/lib-site.mjs on 2026-10-30; the skill copy stays the source, changes go there first and are copied back.` You may extend it (line numbers, img records, og tags, hreflang, `<main>` count, title count, description count) but keep every existing export working. |
| `lib/lines.mjs` | finds the 1-based line number of a tag occurrence in the raw HTML (every FAIL needs `<page>:<line>`) |
| `checks/<rule-id>.mjs` | one file per rule, lowercase id (`checks/met-003.mjs`). Exports `id`, `source` (string, see Sources), `severity` (`P0`, `P1`, `P2`, `W`), and `run(site) -> findings[]` where a finding is `{ rule, page, line, what, status: "FAIL" | "WARN" }`. A rule that cannot judge (no sitemap to read for IDX-002) returns a finding with `status: "SKIP"` and `what` saying why, never a PASS. |
| `rules/<RULE-ID>.md` | the rule's full text pasted from the Sources section below with its source line; the engine refuses to load a check whose rules file is missing (`checks admitted only with a source`) |
| `index.mjs` | `audit(dir, options) -> { dir, pages: [paths], rules: [{ id, severity, source }], findings: [...], lines: [...], pass: boolean, exit: 0 \| 1 }`; `lines` is the full list of `PASS <rule id> <page>` / `WARN ...` / `FAIL <rule id> <page>:<line> <what> (source: <checklist file>)` / `SKIP <rule id> <page> <why>` strings, one per rule per page (site-wide rules such as IDX-001 use the page `/` or the file they judge, `robots.txt`, `sitemap.xml`). `options.rules` (array of ids) limits the run; `options.config` overrides the length numbers. |
| `run.mjs` | the runner: `node tools/audit/run.mjs <folder> [--json] [--only MET-003,MET-001] [--list]`. Prints the lines, exit 1 on any FAIL, 0 otherwise (WARN and SKIP do not fail). `--json` prints the `audit()` object and nothing else. `--list` prints every rule with severity and source, exit 0. Exit 2 on usage error or a missing folder. |
| `fixtures/good/` | a synthetic site of 4 pages (home, two inner pages, one article) with `robots.txt` and `sitemap.xml` that passes every rule with zero WARN. Invented business, invented names, no real place or person; nothing copied from any client folder. |
| `fixtures/bad-<RULE-ID>/` | one copy of the good site per rule, broken in exactly that rule and no other (`bad-MET-003`: an h2 followed by an h4; `bad-MET-001`: a second `<title>`; `bad-LNK-002`: a link to `/missing/`; and so on). For rules with several parts (MET-003 main and skip; A11-007 missing alt and filename alt) one fixture breaking each part is fine: `bad-MET-003-skip`, `bad-MET-003-two-h1`. Fixtures are generated by `fixtures/build-fixtures.mjs` from the good site plus a list of edits (one function per fixture, `t.split(a).join(b)`), committed as files so a reader sees them; the test checks the generator's output equals the committed files. |
| `test/run.mjs` | the tests. Lines start `ok  ` or `FAIL`; last line `OK: N of N checks passed`, exit 0 only when every check passed. Checks: the good site passes every rule with exit 0 and no WARN; each bad fixture produces at least one FAIL for its rule and ZERO FAIL for any other rule, exit 1; the FAIL line shape (`^FAIL [A-Z0-9-]+ \S+:\d+ .+ \(source: .+\)$`); `--json` is valid JSON with `exit` equal to the process exit; `--only` limits the rules; a check without a `rules/<ID>.md` is refused (plant one in a temp copy); `--list` names every rule and source; a missing folder exits 2; every fixture equals its generator output. `OMNIKOM_AUDIT_DIR` points the tests at a copy of `tools/audit/` (the mutants use it). |
| `test/mutate.mjs` | pattern of `tools/departments/test/mutate.mjs` (read it first): `[name, file, exactText, replacement]`, applied with split/join to a temp COPY of `tools/audit/`, one child process per mutant with a 180 s timeout, `OMNIKOM_AUDIT_DIR` set to the copy; caught = exit nonzero AND at least one `FAIL` line in stdout; a crash or a timeout with no FAIL line is NOT a catch. At least one mutant per rule (the rule's comparison disabled, so the bad fixture passes), plus: the exit code always 0; a FAIL line without the source. Last line `N mutants, N caught, 0 survived, 0 target text missing`, exit 0 only then. |
| `README.md` | the library call (`import { audit } from "./tools/audit/index.mjs"`), the runner, the line format, the exit codes, how to add a rule (check file + rules file + bad fixture + test + mutant, all five or it is not admitted), the sources table. The CLI department will wrap this; write the call so a thin wrapper needs nothing else. |

## The rules (the numbers and the text come from the Sources below; a check that is not in this list is out of scope)
Rule texts: shipgate spec 8.0.0, pack files, read 2026-10-30. The skill's checklist copy (`skills/programmatic-enterprise-web-performance/checklist/`)
has the same ids with the text cut short; cite the checklist file in the FAIL line (`source: checklist/web-delivery.md MET-003`) and paste the
full text below into `rules/<ID>.md` together with the spec path `shipgate/spec/packs/web-delivery.md` (or accessibility, search-engines).

- **MET-003** P0 (web-delivery): Exactly one `<main>` with exactly one `<h1>` on public pages (part main; missing-element, duplicate-element);
  part skip: in document order across the whole `<body>`, each `<hN>` after the first heading has N <= the previous heading's level + 1 (going
  up any number of levels is allowed; value-mismatch with both headings). The owner's first ask: this check is the first one you write.
- **MET-001** P0 (web-delivery): Exactly one non-empty `head > title` (an SVG `<title>` is not counted), whose length (Unicode code points of
  its NFC text with whitespace collapsed and trimmed) is <= `titleLength.hardMax`; unique within locale across indexable pages (compared after
  NFKC, case folding and whitespace collapse).
- **MET-002** P1 (web-delivery): A non-empty `<meta name="description">` in `<head>` (with several, the first is judged), length <=
  `descriptionLength.hardMax`, unique across indexable pages as MET-001.
- **MET-004** W (web-delivery): Title or description length outside its `warnMin` to `warnMax` range. WARN, never FAIL.
- **SE-202** P1 (search-engines): Bing minimum lengths: title >= 20 and meta description >= 50 Unicode code points (pages whose `<html lang>`
  primary subtag is zh, ja or ko: title >= 10, description >= 25).
- Length defaults (shipgate spec 8.0.0 `packs/web-delivery.md` line 21, the default adapter config): `titleLength { warnMin: 30, warnMax: 60,
  hardMax: 70 }`, `descriptionLength { warnMin: 70, warnMax: 160, hardMax: 180 }`. Overridable by `options.config` and by a
  `audit.config.json` in the audited folder; WCF-004: `warnMin < warnMax <= hardMax`, else exit 2.
- **URL-009** P0 (web-delivery): On each indexable page: the same canonical string in the canonical tag, `og:url`, the page's own hreflang
  `href` and JSON-LD `WebPage.url`; every hreflang `href` equals the canonical of its target page. In a folder there is no origin: the
  canonical must be present, absolute (`https://`), and its path must normalise (`normPath`) to the page's own path; og:url, hreflang and
  WebPage.url, when present, must equal it exactly. A missing canonical is missing-element.
- **IDX-004** P0 (web-delivery): robots.txt: present at the folder root, references the sitemap (`Sitemap:` line whose path is the sitemap
  file), never disallows a sitemap URL or any indexable page of the folder. (The HTTP parts, 200 and text/plain, are slice 2's and are SKIP here.)
- **IDX-001** P0 (web-delivery): Sitemap URL set equals the set of indexable pages in canonical form; each discrepancy class is its own
  finding: extra (a URL with no page), missing (a page not in the sitemap), non-canonical (a URL that is not the page's canonical), noindex
  (a page with `noindex` listed).
- **IDX-002** P0 (web-delivery): <= 50,000 URLs and 52,428,800 bytes per file; sitemap index when more than one file; valid escaped XML;
  absolute URLs on one origin; unique entries.
- **SE-004** P1 (search-engines): Sitemap `<lastmod>` uses W3C datetime with time and timezone (`YYYY-MM-DDThh:mm:ss` then `Z` or `+hh:mm`);
  a date-only value fails; not in the future. Wrap the skill's existing built-in: copy
  `skills/programmatic-enterprise-web-performance/checks-builtin/check-builtin-se004-idx003-sitemap-lastmod.mjs` to
  `lib/sitemap-lastmod.mjs` with the same copy header, call it as a child process or lift its logic into a function (keep IDX-003's build-clock
  signature as a WARN under id IDX-003).
- **A11-007** P1 (accessibility): every `<img>`, `input[type=image]` and `area[href]` has an `alt` attribute; on `<img>`, `alt=""` (or
  `role=presentation|none`) marks decorative and passes; `input[type=image]` and `area[href]` need a non-empty `alt`, `aria-label` or
  `aria-labelledby`; any other `alt`, trimmed, is not empty, does not match `^[^\s/]+\.(avif|bmp|gif|jpe?g|png|svg|webp)$` (case-insensitive),
  is not equal to the `src` or its last path segment, and, case-folded, is not one of the generic words `image, picture, photo, graphic, icon,
  logo, img` (the spec's `genericAltWords` list for en; cite as such). The browser parts (role=img names, axe rules) are SKIP.
- **LNK-002** P0 (web-delivery): every internal `a[href]` (resolved with `resolveInternal`; fragment-only, `mailto:`, `tel:`, `javascript:`
  out of scope) lands on a page that exists in the folder (an `.html` file, or a non-HTML file such as a PDF or image that exists); a target
  that is missing is status-mismatch; an internal link with `nofollow` in `rel` is forbidden-value; a link to a page's non-canonical form
  (`/about.html` when the page is `/about/`, or `index.html`) is value-mismatch.
- **SCH-001** P0 (web-delivery): one `<script type="application/ld+json">` per page with `@graph`; it parses; it contains a `WebPage` node
  (or subtype: AboutPage, ContactPage, CollectionPage, FAQPage, ItemPage, ProfilePage, SearchResultsPage) whose `@id` is `{canonical}#webpage`
  and a `WebSite` node or `@id` reference `{origin}/#website`; the home page (`/`) carries the full `Organization` node `{origin}/#organization`
  (other pages may reference it by `@id`); every `@id` reference in the block resolves to a node in the same block or, for the organization
  and website ids, in the home page's block. A second ld+json block is duplicate-element; a parse error is a FAIL naming the JSON error.

## How to work
1. Read first: this brief; `tools/departments/test/mutate.mjs` and `tools/departments/test/run.mjs` (the house test shape);
   `skills/programmatic-enterprise-web-performance/scripts/lib-site.mjs` whole; the built-in check named above; `docs/blueprint/23-GROUND-RULES.md`
   section 2 rule 10. Do not read the rest of the skill; do not open any client folder (`E:\Alex Sevilla`, `E:\Francine & Eli`, `sites/`).
2. Build in this order and run the tests after each: reader + runner skeleton + MET-003 with its good and bad fixtures; then the rest of the
   rules one by one, each with fixture, test and mutant before the next. Watched-fail every check: break it, see the FAIL for the right
   reason, restore. A check that passes a fixture it should fail is a bug in the check, not a reason to change the fixture.
3. Scripts go in files, never inline `node -e`. No em dash (the character U+2014) in any file; write a colon or two sentences instead.
4. Never touch files outside `tools/audit/` (the skill copy, the CLI, the blueprint, the charter are the head's). A bug in `lib-site.mjs`
   is a finding: fix your copy, note the fix at the top of your copy, and report it so the head carries it back through the skill sync.
5. No network. Every test blocks nothing because it needs nothing; a fixture is a file.
6. The done report to the head is two lines plus the three pasted outputs below; never claim green without the output in front of you.

# Dashboard screens: example-c

Generated by `contracts/screens.mjs` from the site contract (industry: insurance-agency). Nothing on this page is written by hand.

## Menu

- Pages (11, by type: home 1, product-guide 3, careers 1, about 1, contact 1, faq 1, disclosures 1, privacy 1, terms 1)
- Business details (one form): owner + Omnikom only
- Articles: agents/members see only their own
- Team: agents/members see only their own
- Reviews: owner + Omnikom only
- Questions and answers: owner + Omnikom only
- Legal and compliance text: owner + Omnikom only
- Photos and files: agents/members see only their own
- Redirects: owner + Omnikom only
- Lead inbox (inbox): agents/members see only their own
- Products: owner + Omnikom only

Every content screen has the same publish bar: **Save draft** (a new version, the site does not change) · **Preview** · **Publish** (runs the checks below, rebuilds only this site) · **History** (every version with who and when; restore = a new version). Leads have no publish bar.

## Publish checks (from the contract, shown to the client in plain words when one fails)

- Every required field filled; text within its length; no placeholder text ("[client to ...]", "TODO", "lorem ipsum").
- Photos: alt text, wide enough, "we have the right to publish" ticked, location data stripped by the upload.
- Facts and numbers shown to visitors carry a source link and date.
- Locked text (licences, disclosures, consent) unchanged unless Omnikom recorded a sign-off.
- Then the site checks (SEO gate, render gate); a failure deploys nothing.
